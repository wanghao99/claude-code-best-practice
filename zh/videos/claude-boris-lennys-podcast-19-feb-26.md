[`5:37`](https://youtu.be/We7BZVKbCVw?t=337) 好，那我们就顺着“回到 Anthropic 之后做的事”这条线聊。这期节目上线时差不多是 Claude Code 发布一周年，所以我想花点时间回顾你们造成的影响。最近有份报告出来，你肯定看到了，SemiAnalysis 做的，说现在 GitHub 上 4% 的 commit 都由 Claude Code 编写，他们预测到年底会占 GitHub 全部 commit 的五分之一。他们的原话是：就在我们眨眼的工夫，AI 吞下了整个软件开发。就在我们录这期的今天，Spotify 刚发了这么一条大标题：得益于 AI，他们最优秀的开发者从 12 月起就没写过一行代码。越来越多最资深的高级工程师，包括你，都在公开说自己不写代码了，全是 AI 生成的，很多人甚至不再看代码了。我们能走到今天，很大程度上要归功于你起的这个小项目，和你团队过去一年把它做大的过程。很想听听你对这一年的回顾，以及你们的工作带来的影响。这些数字真的很疯，对吧？全世界 4% 的 commit，比我当初想象的多太多了。而且就像你说的，感觉还只是起点。这些还只是公开 commit。我们其实认为，如果看私有仓库，比例要比这高不少。对我来说最疯的甚至不是现在的数字，而是我们的增长速度：你去看 Claude Code 几乎任何指标的增长率，它都还在加速，不只是往上走，而是越走越快。我刚开始做 Claude Code 时，它就只是打算做一个小 hack。那时候 Anthropic 大方向上知道我们想上一个编程产品。很长一段时间里，我们造模型的方式都符合我们关于“怎么造出安全模型”的心智模型：模型先变得非常擅长编程，再变得非常擅长用工具，再变得非常擅长使用计算机，大概就是这条轨迹。我们做这件事做了很久。看我最初加入的那个团队——当时叫 Anthropic Labs——其实 Mike Krieger 和 Ben Mann 刚把这个团队重新拉起来做第二轮。这个团队做出了一些相当酷的东西：我们做了 Claude Code，做了 MCP，做了桌面应用，你能看到这条思路的种子：先是编程，再是工具使用，再是计算机使用。而这对 Anthropic 重要的原因，还是安全，又绕回那句话：AI 越来越强大、能力越来越强。过去一年发生的事情是，至少对工程师而言，AI 不只是写代码，它不只是对话伙伴，而是真的会用工具、会在世界中行动。而现在有了 co-work，我们开始看到非技术人群的这场转变。对很多用对话式 AI 的人来说，这可能是他们第一次用上真正会“行动”的东西：它真的能用你的 Gmail，能用你的 Slack，能替你做所有这些事，而且做得相当好。往后只会更好。所以对 Anthropic 来说，很长时间里都有一种“我们想做点什么，但不清楚做什么”的感觉。我加入时先花了一个月瞎折腾，做了一堆奇怪的原型，大多数没发布，离发布也远，主要是摸清模型能力的边界。然后我又花一个月做 post-training，去理解研究那一侧。说实话，作为工程师，我一直觉得：要把工作做好，你必须理解你所在那一层的下一层。传统工程里，你做产品，就想理解基础设施、运行时、虚拟机、语言，你构建于其上的那套系统。而在 AI 里，你真的必须在某种程度上理解模型，才能做好工作。所以我绕了这么一小段路，回来之后就开始做原型，也就是后来的 Claude Code。最早那个版本，我还有当时的录像，因为夏天我录了个 demo 发了出去，那时它叫 Claude CLI。我就是展示了一下它怎么用几个工具，而最让我震惊的是：我给了它一个 bash 工具，我问它“我在听什么音乐”，它竟然能用那个工具写代码，查出我在听什么音乐。这是最疯狂的事，对吧？因为我完全没有教过模型“这个问题用这个工具”之类的任何东西。模型拿到了工具，自己想明白怎么用它来回答我这个我都不确定它能回答的问题。于是我开始更多地做原型，发了个帖子，在内部宣布了一下，收获两个赞。两个赞，这就是当时反响的全部。我想是因为在大家心里，提到编程工具，想到的是 IDE，是那些相当精密的环境，没人觉得这东西可以是基于终端的，用终端设计显得有点怪，虽然那本来也不是刻意的设计。但我从第一天起就在终端里做它，因为头几个月只有我一个人，那是最省事的构建方式。对我来说这其实是个挺重要的产品课：一开始要故意让资源少一点。后来我们开始考虑该做别的什么形态，最后决定在终端上再守一阵子，最大的原因是模型进步太快了，我们觉得没有别的形态能跟得上它。说实话，那阵子我一个人纠结该做什么，这一年里 Claude Code 就是我脑子里唯一想的事。深夜里我就在想：模型在持续变强，我们怎么办？我们怎么可能跟得上？终端说实话是我唯一想到的主意。结果发布之后很快就流行起来了，在 Anthropic 内部火了，日活直接起飞。其实很早，发布之前，Ben Mann 就催我做一张 DAU 图，我说是不是还太早，现在就画吗？他说画。然后那条曲线几乎是立刻就垂直往上。到了 2 月，我们对外发布。其实有件事大家不太记得：Claude Code 刚发布时并不是爆款。它确实收获了一批用户，很多早期采用者一眼就懂了，但真正让所有人理解这是什么东西，花了好几个月。再说一次，它实在太不一样了。现在回头看，Claude Code 能成的一部分原因是潜在需求：我们把工具带到人们所在的地方，让既有工作流变容易一点；但同时也因为它是终端里的东西，有点出人意料，某种程度上有点“异星感”，所以你得心态开放，得学着用它。当然现在 Claude Code 已经无处不在了：iOS 和 Android 的 Claude 应用里有，桌面应用里有，网站上有，IDE 扩展、Slack、GitHub 里都有——这些工程师待的地方就显得亲切多了——但起点不是这样的。所以一开始，这东西居然有用，本身就有点出人意料。随着团队变大、产品长大，它对越来越多的人越来越有用，全世界的人，从小的创业公司到最大的 FANG 巨头都在用，开始给我们反馈。回头看，这真是一段令人谦卑的经历，因为我们一直在向用户学习，而最让人兴奋的是：说实话我们谁也不知道自己在干什么，我们只是和所有人一起摸索，而最好的单一信号就是用户的反馈。所以我被打动了一次又一次。不可思议，今天的世界里事情能变得多快。你一年前发布了它，虽然人们不是第一次能用 AI 写代码，但一年之内，软件工程这个职业整个被改变了。以前有各种预言：“AI 写的代码会占 100%，所有代码都由 AI 写”，大家都说：不可能，疯了，你在说什么。现在则是——

[`13:53`](https://youtu.be/We7BZVKbCVw?t=833) ——当然了，一切正按他们说的发生。只是现在事情移动、变化得太快了。

[`13:59`](https://youtu.be/We7BZVKbCVw?t=839) 是，真的很快。去年 5 月的 Code with Claude 大会，那是我们作为 Anthropic 办的第一场开发者大会。我做了个简短演讲，演讲后的问答环节，有人问你们对年底有什么预测。我在 2025 年 5 月的预测是：到年底，写代码可能已经不需要 IDE 了，我们会开始看到工程师不再做这件事。我记得整个房间的人都倒吸一口气。在当时这是个很疯狂的预测。但在 Anthropic，我们思考问题的方式就是指数，这是刻在 DNA 里的。你看我们的联合创始人，有三位是 scaling laws 论文的前三作者。所以我们真的用指数思考。当时如果把“Claude 写的代码百分比”的指数曲线画出来，顺着线一延，年底越过 100% 是显而易见的，哪怕完全违背直觉。我所做的不过是顺着线画下去。11 月，这事在我自己身上成真了，此后一直如此，我们也开始在很多不同客户身上看到同样的事。我觉得你刚才分享的这段历程特别有意思，就是那种“随手玩玩，看看会发生什么”。聊 OpenClaw 时这个话题也老出现：Peter 就是随手玩玩，然后就长出一个东西。感觉这是 AI 领域很多最大创新的核心要素：人坐在那里瞎试，把模型推到大多数人推不到的地方。

[`15:23`](https://youtu.be/We7BZVKbCVw?t=923) 这就是创新的规律，你没法强求。创新没有路线图。你只能给人空间，或者用“安全感”这个词吧：心理上的安全感——失败了没关系，80% 的点子是坏点子也没关系。同时你也得让他们负点责：点子不行，就止损，转下一个，而不是追加投入。Claude Code 早期，我完全不知道这东西会有用。哪怕 2 月发布时，它大概只写我 20% 的代码，撑死。5 月时大概 30%，我大部分代码还在用 Cursor。到 11 月才过 100%。所以花了一阵子。但从最早那天起，我就隐约觉得自己摸到了什么。我每个晚上、每个周末都在上面折腾，好在我太太非常支持。就是那种“这里面有东西”的感觉，虽然不清楚具体是什么。有时候你摸到一根线头，就只管往外拉。

[`16:53`](https://youtu.be/We7BZVKbCVw?t=1013) 100% 由 Claude Code 写。从 11 月起，我没手改过一行。就是这样。我确实会看代码。我认为我们还没到可以完全放手的地步，尤其是有很多人同时跑着程序的时候：你得确保它是对的，确保它是安全的等等。我们还有 Claude 对所有东西做自动 code review。在 Anthropic，Claude review 了 100% 的 PR。之后仍然有一层人工 review，你还是需要这些检查点，还是要有人看代码——除非是那种纯原型代码，反正也不会跑在任何地方，就是个原型。
