[`0:01`](https://youtu.be/julbw1JuAz0?t=1) 你可是 O'Reilly 那本第一本 TypeScript 书的作者。

[`0:04`](https://youtu.be/julbw1JuAz0?t=4) 对，我在日本一个小镇上发现了那本书的日文版，那真是最酷的时刻。然后我意识到我已经完全不记得 TypeScript 了。现在我们已经到了这个地步：Claude Code 平均写下 Anthropic 大约 80% 的代码。我每天大概提 10 到 20 个 PR，每一个都 100% 由 Opus 4.5 和 Claude Code 完成，我一行都没手动改过。

[`0:22`](https://youtu.be/julbw1JuAz0?t=22) Andrej Karpathy 发帖说，他作为程序员从未像现在这样感到落后。

[`0:26`](https://youtu.be/julbw1JuAz0?t=26) 这也是我自己非常纠结的事。模型进步太快，旧模型上行得通的想法，新模型上可能就行不通。我对当下这个时刻的一个比喻，是 1400 年代的印刷机，因为那时有一群会书写的抄写员。

[`0:42`](https://youtu.be/julbw1JuAz0?t=42) 而雇这些抄写员的国王里，有些自己都不识字。

[`0:45`](https://youtu.be/julbw1JuAz0?t=45) 想想抄写员的下场：他们不再当抄写员了，但从此多出了"作家"和"作者"这两个类别，这群人从此存在。他们存在的原因是文学市场的规模……——加入世界顶级 AI 实验室之后，你的第一个 pull request 被拒了，会怎样？不是代码写得差，而是因为它是你手写的。这正是 Boris Cherny 加入 Anthropic 时遇到的事。Boris 是 Claude Code 的创造者和工程负责人。加入 Anthropic 之前，他在 Meta 工作了 7 年，负责 Instagram、Facebook、WhatsApp 和 Messenger 的代码质量，也是全公司最高产的代码作者和 code reviewer 之一。在本期节目里，我们聊了 Claude Code 如何从一个副业项目变成增长最快的开发工具之一，以及 Anthropic 内部关于"到底要不要发布它"的争论；Boris 每天零手写代码交付 20 到 30 个 PR 的日常工作流，以及当 AI 写了所有代码时 code review 怎么做；还有为什么 Boris 认为我们正身处一个堪比印刷机的变革时代，哪些工程技能现在更重要、哪些不再重要。如果你想了解离 AI coding agent 最近的人今天到底怎么写软件，以及这对我们其他工程师意味着什么，这期就是为你准备的。本期节目由 Statsig 赞助，它是集 feature flag、分析、实验等能力于一体的统一平台。节目说明里有关于它和我们本季其他赞助商 Sonar、WorkOS 的更多信息。——你是怎么进入科技行业、软件工程和编程这一行的？

[`2:14`](https://youtu.be/julbw1JuAz0?t=134) 这就说来话长了。我觉得有两条平行的路，后来交叉到了一起。大概 13 岁的时候，我开始在 eBay 上卖自己的旧宝可梦卡。我发现 eBay 上居然可以写 HTML。我去看别人挂的宝可梦卡页面，发现有些人的页面有大号颜色、大字体什么的。然后我发现了 blink 标签，从此对 blink 标签着了迷。

[`2:41`](https://youtu.be/julbw1JuAz0?t=161) 给页面加上 blink 标签，我那张卡就能卖 99 美分而不是 49 美分什么的。我就是这样学会 HTML 的，后来又买了本 HTML 书系统地学。第二件事大概也在初中：我们用那种老式 TI-83 图形计算器上数学课。我发现，只要把数学考试的答案编进计算器，考试就能考得更好。于是我就写小程序把答案存进去。后来考试变难了，我没法直接存答案，只能编"解题器"，因为我事先不知道系数之类会是什么。再下一年数学更难了，我只好从 BASIC 降到汇编，就为了让程序跑得快一点。

[`3:28`](https://youtu.be/julbw1JuAz0?t=208) 哇，所以你高中就下到汇编了。

[`3:30`](https://youtu.be/julbw1JuAz0?t=210) 应该是初中或高中，大概八九年级。后来我发现，全班同学都开始意识到我手里有解题器，还有点眼红，于是我买了根串口线，好分享给他们。结果下一次数学考试，全班都拿了 A。老师就问：怎么回事？最后她弄明白了，说：行，这次饶了你们，下不为例。但对我来说，这一切都非常实用主义。我学校里学的是经济学，后来干脆退学去创业，我从来没想过编程会成为一种职业。编程对我一直是件很实用的事，是做出东西、做出有用东西的手段。第一个创业项目是我和朋友们想搞大麻，于是做了个大麻评测创业公司。我们做了个网站，给各家药房打电话，想拿样品帮他们评测，结果还真小火了一把。后来我更感兴趣的是——当时根本没人做这类检测——于是我进入了化学检测、化学分析这个方向。之后又做了好几个创业项目，还挺早就加入了 YC，是帕洛阿尔托一家 YC 创业公司的第一批员工。

[`4:54`](https://youtu.be/julbw1JuAz0?t=294) 你当时是怎么决定一个创业接一个创业的？

[`4:57`](https://youtu.be/julbw1JuAz0?t=297) 说直觉吧。创业这事的路径从来不线性，永远在 pivot、pivot、pivot。你必须搞清楚市场要什么、用户要什么，而答案永远不是你想的那个。你总要去试，但想法始终只是假设，然后几乎总要 pivot 一次、两次、三次。在那家医疗软件公司——叫 Agile Diagnosis——是挺早期的 YC 公司，大概 2011、2012 年那会儿，做面向医生的医疗软件。当时的想法是：临床决策方案每家医院差别都很大，而芝加哥有一家医院的心脏症状方案特别好，我们就想：如果全美的医院都用同一套方案，疗效会不会更好？于是我们试着把它标准化，做了一套给医生用的决策树软件。软件是我写的，团队就我们几个人，非常小。它跑在浏览器里，我还记得那是 Internet Explorer 6 的年代，医院用的就是那个，

[`6:06`](https://youtu.be/julbw1JuAz0?t=366) 因为它是一棵可视化决策树，我还写了个 SVG 渲染器。产品上线后我们看 DAU 曲线，平得一条线，怎么也想不通。当时我们总部在帕洛阿尔托，正和几家医院做试点，包括 UCSF。我那时骑摩托车，就骑车去 UCSF，跟了医生两天，就想看看他们到底怎么用。我这才发现，医生根本没时间坐下来用电脑，因为你正在看一个病人，

[`6:42`](https://youtu.be/julbw1JuAz0?t=402) 到下一个病人之前大概只有 5 分钟，这 5 分钟里你要穿过走廊、走到电脑站、开一台完全老掉牙的电脑——光开机就要 3 分钟，再打开 Internet Explorer 6 又要 30 秒，然后打开我们做的应用，再登录，5 分钟就到了，根本没时间用。于是我们把整个产品重写到 Android 上，他们还是不用。我们这才意识到：医生查房时身后跟着一队住院医，这种场景其实是社交场景，关键是他们要维持权威形象，他们不想被人看到在玩手机。然后我们又 pivot 了。到这一步我们想，好吧，也许医生不是目标用户，也许该给护士、放射科技员这些人用。而我在这时候离开了，因为我觉得这已经离我想做的事太远了。对我来说最有意思的就是找 product-market fit，因为它永远充满意外。你不能只抱一个宏大想法，因为这个想法大概率是错的，你只能形成假设，顺着走下去，看什么是对的。——听你讲这段故事也很有意思，因为很多创业成功故事我们只听到成功和路径本身。首先，很多创业其实都是这样的；其次，让我触动的是，你当时是被招去做软件工程师的，对吧？那还是在"产品工程师"这些说法出现之前。但你就是骑上摩托、跑到现场、跟访用户，搞清楚他们怎么用、为什么不用、去获取想法。我觉得这是当年优秀软件工程师的特质，今天也是。你给我的感觉不是盯着某项技术，而是盯着结果。

[`8:31`](https://youtu.be/julbw1JuAz0?t=511) 对。你看，工程师有很多种，做事的方式也有很多种。就算在我们现在的团队里，你看 Jared Sumar 这样的工程师，技术头脑惊人，对系统的理解超过我见过的任何人。你需要这样的人，需要这种深度。而对我而言，工程一直是很实用的事，我一直是个通才——做设计也好、做工程也好、做用户研究也好，都无所谓。——AI 与软件工程的投资逻辑很简单：AI 写的代码越多，需要验证的代码就越多。但有个问题：AI 生成的代码平均比人写的代码更难验证。所以有了 Sonar，SonarQube 的开发商。作为 AI 时代的关键验证层，Sonar 保证 AI 带来的速度和产量不会损害你的代码库。Sonar 的竞争壁垒建立在 17 年的专业积累之上，这是任何基础模型都无法复制的。我们说的是符号执行、跨仓库数据流追踪这类深度分析引擎——它们模拟代码的真实行为，而不只是代码写了什么。为了弥合 AI 生产力与代码质量之间的鸿沟，Sonar 发布了 SonarQube MCP server。这个工具相当于 AI 应用与 SonarQube 平台之间的通用翻译器：借助 Model Context Protocol，它让 Claude Code、GitHub Copilot、Cursor 这些 AI 工具直接使用 SonarQube 的分析能力。不必来回切换上下文，你的 AI agent 就成为名副其实的 code review 与质量保障副驾，能够分析代码片段中的问题、按严重程度过滤 bug，甚至在你提交代码前检查项目的 quality gate 状态。无论你用的是编码助手，还是全面 agent 化的工作流，Sonar 提供的自动化验证已被 75% 的财富 100 强企业依赖。它要让开发者放心创新、不怕弄坏代码库。访问 sonarsource.com/pragmatic，了解 Sonar 如何让你有信心以 AI 的速度开发。——接着聊 Boris 的职业生涯和他在创业公司学到的东西。我的第一份工作，大概是 16 岁吧，我就是想买一把电吉他。于是我开始接自由职业的活，我想："好吧，那就做网站。"那时 Fiverr 还不存在，有一些别的接单网站。我挂了个网页，开始投标接活。第一笔收入，我一分不剩全拿去买了电吉他。但这一切都非常实用主义，对吧？因为在这种模式下，你得自己做工程、自己记账、自己做设计、自己谈客户，我一直都是这么过来的。——做了几次创业之后，你进了 Facebook，也就是现在的 Meta，一待就是七年。能讲讲你在那里做了什么、学到了什么吗？你晋升也很快，七年里升了四级，这段经历你带走了什么？

[`11:39`](https://youtu.be/julbw1JuAz0?t=699) 好，我从 Facebook Groups 做起，Vlad Klesnikov 招我进来的，我印象里他现在还在 Facebook，应该在别的团队了。那段经历其实挺酷，我身边有一大群早期 JavaScript 圈的人。我做过一堆 JavaScript 的东西，有意思的是我总跟这批人相遇。Vlad 做过 Bolt.js，就是那个驱动 Ads Manager、后来演变成 ReactJS 的框架。我后来还不断碰到这类人。总之我在做 Facebook Groups，特别兴奋，因为它的使命是把人和他们的社区连接起来，这正是吸引我的地方。那时我是重度 Reddit 用户，从青少年时期就是，因为除了那儿我不认识任何会写代码的人，甚至上了大学也不认识。

[`12:37`](https://youtu.be/julbw1JuAz0?t=757) 说实话，我一直有点不好意思提这事，因为我觉得这太书呆子气了。这是我掌握的一门技能，但我想当酷小孩，没法告诉别人我会编程，太宅了。直到某个时候我在 Reddit 上发现了一个编程社区，我完全震惊了：居然还有别人喜欢这个，这么奇怪、这么小众的爱好。能找到同类、建立这种连接，太让人兴奋了，所以我就想做点相关工作，想以某种方式做贡献。我在 Facebook Groups 干了一阵，中间还有各种项目，就不一一细说了。后来我成了 Facebook Groups 的 tech lead，慢慢长到了那个位置。组织在长大，工作性质也真的变了：从亲手构建，变成大量写文档、做协调、给别人派活。公司文化也在变，早期 Facebook 的文化在消失，文档来了，alignment 会议来了，围绕隐私、安全这类基础的工作多了很多——说实话，早期为了增长砍掉了大量这类角落，但债总归要还，就是那段时间还的。之后我在 Instagram 干了几年，说来也是个好笑的故事。我妻子拿到一个工作 offer，特别兴奋，跑来跟我说："嘿，我拿到这个 offer 了，但我们得搬家，行吗？"我说："行啊，没问题。"我做科技的，远程在哪儿干活都行。工作在哪儿？她说，在一个叫 N 的地方。我问，那是哪儿？——N 在日本乡下。那是——

[`14:17`](https://youtu.be/julbw1JuAz0?t=857) 而且时区也不同。

[`14:20`](https://youtu.be/julbw1JuAz0?t=860) 差 12 个小时还是多少来着。

[`14:22`](https://youtu.be/julbw1JuAz0?t=862) 差不多吧。对，大概是 2021 年。

[`14:24`](https://youtu.be/julbw1JuAz0?t=864) 哇。

[`14:25`](https://youtu.be/julbw1JuAz0?t=865) 于是我得找一个愿意"接收"我的团队，因为公司有一些古怪的 HR 规定，规定你必须在哪个时区、必须和哪个团队坐在一起之类。东京有一个 Instagram 的小型初创团队，Will Bailey 带队，他也是做出 Instagram Stories 的人，他当了我一阵经理，我们决定一起把这个团队做大。我在 N 远程办公，团队大部分人在东京。那段时间我开始折腾 Instagram 的技术栈，感受太震撼了：Facebook 拥有全世界最好的 web 服务栈，从 Hack 语言到 HHVM 运行时，到 GraphQL 作为传输层，再到 Relay 这些客户端库，一切都高度优化，加上 React，全世界没有第二个这么好的开发栈。然后我到 Instagram 这边，是 Python，类型检查器不好使，点击跳转定义不好使，Django 是七拼八凑的，再加一层 Cython 运行时，基本什么都不好使。我加入的是 Instagram 在日本的 Labs 团队，任务是找到 Instagram 的下一个大东西。我们试了些东西，但我很快就意识到，在这个栈上我根本发挥不出效率，因为它太糟糕了，于是我干脆去做 Dev Infra，因为我们必须把它修好。我们做了几个项目：一个是把 Python 迁移到 Facebook 的大单体仓库，另一个是从 REST 迁到 GraphQL。这些项目当时还在进行中——这种事要几百名工程师干很多年，代码库太大，迁移太大。现在嘛，快多了。

[`16:16`](https://youtu.be/julbw1JuAz0?t=976) 对，用我们现在这些 AI 工具，迁移确实是个很好的用例。

[`16:21`](https://youtu.be/julbw1JuAz0?t=981) 对，简直是完美用例。之后我越扎越深。到我离开 Instagram 时，我已经在做 Dev Infra、牵头好几个迁移项目。也是在那儿我和 Fiona Fun 有了交集，她现在是 Claude Code 团队的 manager。我和她共事，她是一位非常出色的领导者，在科技行业有惊人的深度和阅历。我当时就觉得，这个团队没有比她更合适的 manager 了。后来我又开始做代码质量，在 Instagram 的工作面就扩大了一些。到我离开时，我负责整个 Meta 的代码质量，Instagram、Facebook、Messenger、WhatsApp、Reality Labs 这些代码库的质量都归我管。在 Meta 有个叫 Better Engineering 的项目，大概是 2016 还是 2018 年，Zuck 强制要求全公司每个工程师 20% 的时间必须用来还技术债。

[`17:17`](https://youtu.be/julbw1JuAz0?t=1037) 哦，有意思。

[`17:19`](https://youtu.be/julbw1JuAz0?t=1039) 我们就叫它 Better Engineering。

[`17:22`](https://youtu.be/julbw1JuAz0?t=1042) 嗯。其中一部分是自下而上的，团队最清楚自己该修哪些技术债；还有一部分是自上而下的，比如要做超大规模迁移，迁移到新的语言特性、新框架等等。在 Facebook 的体量下，每年这种迁移有数万项。我开始牵头这一切后，很快就意识到这事需要更多章法：没有目标，没人说得清产出是什么，也没有任何跟踪。于是我们做了一系列东西。一个思路是把各种代码质量工作集中排定优先级；第二件事是搞清楚代码质量对工程生产力的影响，结果发现影响非常大。

[`18:04`](https://youtu.be/julbw1JuAz0?t=1084) 你们怎么度量的？发现了什么？

[`1:31:59`](https://youtu.be/julbw1JuAz0?t=5519) 可以肯定地说，在这一切 AI 之前你就是一位非常出色的软件工程师，而且现在也极高产，既是团队一员，也单独作战。想问：在"软件工程师"这个身份之下，哪些技能今天仍然同等值钱、甚至更值钱？哪些不那么值钱了，或许最好留在过去？——好。最好留在过去的，可能是对代码风格、编程语言这类东西的强烈执念。我等不及翻过这些无休止的语言之争、框架之争了，因为模型随便用什么语言、什么框架都行，你不满意，它直接给你重写一遍，所以这些根本不再重要。今天仍然非常要紧的，是做事有条理、以假设驱动。这既重要于产品设计——在这个一切都被颠覆、必须想清楚下一步做什么的世界里，人人都在琢磨这个问题；也重要于工程日常，比如 debug，你就必须非常有条理。模型能做、也能帮很多忙，但我们仍处在过渡点，你还是得自己有这门手艺。六个月后还要不要，我不知道。另外更值钱的技能是好奇心，和愿意跳出自己泳道的开放心态。如果你在做工程，同时又真正理解业务，你就能做出特别棒的产品。我觉得继 Claude Code 之后，下一个十亿美元级产品——不管哪家创业公司成为下一个万亿级公司——很可能就是某个有酷想法的人，他的大脑能同时横跨工程、产品和业务，或者设计加财务加别的什么。人会越来越跨学科，这会得到越来越高的回报。所以在某种意义上，我觉得今年将是通才之年。还有一个实际上一直被奖励的技能，是短注意力跨度。

[`1:34:11`](https://youtu.be/julbw1JuAz0?t=5651) 现在轮到它被奖励了。——是啊。你看，青少年们刷短视频、刷各种东西，我某种程度上觉得这对社会挺危险，因为你需要能深度思考、能沉潜琢磨想法的人，而不是很快跳到下一个念头。但某种意义上，今年大概会是奖励它的那一年，简直是 ADHD 之年，因为对我的工作来说，内容已经变成了在多个 Claude 之间来回跳，变成了管理一群 Claude。所以重点不再是深度工作，而是我切换上下文的能力有多强：能不能非常快地在多个不同上下文之间跳来跳去。

[`1:34:52`](https://youtu.be/julbw1JuAz0?t=5692) 我能补充一点吗？从你说的一切来看，也许还该加上"适应性"。你说了 ADHD、来回跳，当然你以前也非常擅长深钻一件事。而你身上让我印象深刻——可能对别人也一样——的就是你对调整工作方式异常开放，愿意看什么方式适合当前阶段，尤其是在一切都在变的时候。我想唯一确定的是：下一个模型出来，一切又会再变。你需要好奇心，也需要对改变工作方式保持开放，对吧？

[`1:35:25`](https://youtu.be/julbw1JuAz0?t=5725) 对。——最后，有什么书想推荐？——我掉进过一个兔子洞。他是写《三体》的那位，但他其实还有很多其他非常好的书，我特别喜欢他的短篇，他出过几本短篇集，我是个大书迷。对刚接触科幻、想要偏硬核科幻的朋友，我特别推荐 Charles Stross 的《Accelerando》，这本书我完全推荐，它 essentially 是未来 50 年的产品路线图：从起飞开始发生、AI 奇点，一路写到一群龙虾集体意识绕着木星转，太精彩了。我觉得它真正抓住的是那种节奏——越来越快、越来越快、越来越快的加速感，和当下的感觉非常吻合。技术侧，我强烈推荐《Functional Programming in Scala》。哪怕语言选择已经不那么重要了，函数式编程里有一门艺术，就是能教会你把代码写得更好，它会教会你用类型思考。读这本书很关键的一点是把习题也做掉。我把整本习题大概做了三遍，太棒了。它真的会把"函数式类型"这个观念敲进你脑子里，从此你想忘都忘不掉。
