## 背景

有了 1M token 的上下文窗口，Claude Code 能更可靠地处理更长的任务——但如果你不有意识地管理会话，它也为上下文污染打开了大门。会话管理比以往任何时候都重要：什么时候重新开始、什么时候压缩（compact）、什么时候回退（rewind）、什么时候交给 subagent。

## 上下文、压缩与上下文腐化速览

上下文窗口是模型生成下一条响应时能一次"看到"的全部内容。它包括你的系统提示词、到目前为止的对话、每一次工具调用及其输出，以及每个被读过的文件。Claude Code 的上下文窗口有 **一百万 token**。

遗憾的是，使用上下文有一点代价——**上下文腐化（context rot）**。随着上下文增长，模型性能会下降，因为注意力被摊到更多 token 上，较早且无关的内容开始干扰当前任务。对 1M 上下文模型来说，某种程度的上下文腐化大约出现在 **~300-400k token** 处，但它高度依赖具体任务——不是一条硬性规则。

上下文窗口是硬截止。接近末尾时，你需要总结任务并在新的上下文窗口里继续——这就是**压缩（compaction）**。你也可以自己主动触发压缩。

## 每一轮都是一个分叉点

Claude 完成一轮之后，你接下来的选项多得有些出人意料：

- **继续（Continue）** —— 在同一会话里发送下一条消息
- **/rewind（esc esc）** —— 跳回之前的某条消息，从那里重试
- **/clear** —— 开始新会话，通常带上你从刚学到的东西里提炼出的任务简报
- **压缩（Compact）** —— 把到目前为止的会话总结成摘要，在摘要之上继续
- **Subagent（子代理）** —— 把下一块工作交给一个拥有干净上下文的 agent，只把结果拉回来

最自然的做法当然是继续，但另外四个选项的存在就是为了帮你管理上下文。

每个选项向前携带的既有上下文量各不相同：

| 全新会话 | Compact | Subagent | Rewind | Continue |
|:---:|:---:|:---:|:---:|:---:|
| 只有你的简报 | 有损摘要 | 全过程 + 结果 | 保留前缀、截断尾部 | 全部保留 |
| *一点也不保留* | | | | *全部保留* |

## 什么时候开始新会话

新的 1M 上下文窗口意味着你现在可以更可靠地做更长的任务——例如从零构建一个全栈应用。但并不是说模型上下文还没用完，就不该开新会话。

**通用经验法则：开始新任务时，也应当开始新会话。**

灰色地带是那些相关联的任务：其中一部分上下文仍然必要，但不是全部。例如为你刚实现的功能写文档。虽然可以开新会话，但 Claude 得重新读那些文件，更慢也更贵。既然写文档可能不是对智力高度敏感的任务，多出来的上下文大概率值得换来效率。

## 用回退代替纠正

如果让 Thariq 只挑一个标志良好上下文管理的习惯，那就是 **rewind（回退）**。

在 Claude Code 里，连按两次 Esc（或运行 `/rewind`）可以跳回之前任何一条消息，并从那里重新提示。那个点之后的消息会从上下文中丢弃。

**纠正**（尝试 A 失败后说"不对，试试 B"）会把失败的尝试留在上下文里：
> context = 文件读取 + 2 次失败尝试 + 2 次纠正 + 最终修复

**回退**（回到失败尝试之前，带着学到的经验重新提示）更干净：
> context = 文件读取 + 1 条有据可依的提示 + 最终修复

回退往往是更好的做法。例如，Claude 读了五个文件，尝试一种方案，没有成功。你的本能可能是输入"这没用，改试 X"。但更好的做法是回退到刚读完文件之后，带着学到的经验重新提示："别用方案 A，foo 模块没有暴露那个接口——直接上 B。"

你还可以用 **"summarize from here"（从这里总结）**，让 Claude 总结它的学习成果并生成一条交接消息，有点像未来的自己试过某条路没走通之后，给上一个迭代的 Claude 留的话。

## 压缩还是全新会话

会话一旦变长，你有两种减负方式：`/compact` 或 `/clear`（重新开始）。它们感觉相似，行为却大不相同。

**压缩（Compact）** 让模型总结到目前为止的对话，然后用这份摘要替换历史。它是有损的——你把"什么重要"的判断交给了 Claude，但你自己一个字都不用写。Claude 在收录重要的学习成果或文件时可能会更全面。你也可以通过附带指令来引导它（`/compact focus on the auth refactor, drop the test debugging`）。

- **任务中途**，保持势头——细节可以模糊
- 便宜，继续干

**全新会话 + 简报**（`/clear`）意味着由*你*写下重要内容（"我们在重构 auth 中间件，约束是 X，重要的文件是 A 和 B，方案 Y 已排除"），然后干净起步。更费事，但最终的上下文里装的是*你*认为相关的东西。

- 下一步是**高风险**操作——从 100K 的探索里找到一条关键事实
- 更费事，更精确

## 什么导致糟糕的压缩？

如果你运行过很多长会话，可能注意到某些时刻压缩会特别糟。当模型无法预测你的工作走向时，就可能发生糟糕的压缩。

例如，自动压缩在一次漫长的调试会话之后触发，总结了这次排查。你的下一条消息是"现在修一下我们刚才在 bar.ts 里看到的另一个警告"。但因为会话聚焦于调试，那个另外的警告可能已经从摘要里丢掉了。

这一点尤其棘手：由于上下文腐化，模型在压缩时正处在智能最低的点。有了一百万上下文，你就有更充裕的时间，带着对接下来要做什么的描述去主动 `/compact`。

## Subagent 与全新上下文窗口

Subagent 是上下文管理的一种形式，适合你预先知道某块工作会产生大量之后不再需要的中间输出的场景。

当 Claude 通过 Agent 工具派生一个 subagent 时，这个 subagent 会获得自己全新的上下文窗口。它想做多少工作都行，然后综合自己的结果，只有最终报告回到父级。

心智测试：**我之后还需要这些工具输出本身，还是只需要结论？**

探索噪音会在 subagent 退出时被垃圾回收——20 次文件读取、12 次 grep、3 条死胡同——只有最终报告返回父级上下文。

虽然 Claude Code 会自动调用 subagent，但你可能需要明确告诉它这么做。例如：

- "起一个 subagent，按下面这份规格文件验证这项工作的结果"
- "分出一个 subagent 通读另一个代码库，总结它如何实现 auth 流程，然后你按同样的方式自己实现"
- "根据我的 git 改动，分出一个 subagent 给这个功能写文档"

## 总结

当 Claude 结束一轮、你即将发送新消息时，你正面临一个决策点。随着时间推移，Claude 会自己处理这件事，但目前，这是你引导 Claude 输出的方式之一。

| 场景 | 选择 | 原因 |
|-----------|-----------|-----|
| 同一任务，上下文仍然相关 | **Continue** | 窗口里的一切都还在承重——别为重建它买单 |
| Claude 走上了错误路径 | **Rewind**（连按两次 Esc） | 保留有用的文件读取，丢掉失败尝试，带着经验重新提示 |
| 任务中途，但会话已被过时的调试/探索撑大 | **/compact \<提示\>** | 省力；由 Claude 决定什么重要。需要时用提示引导它 |
| 开始一个真正的新任务 | **/clear** | 零腐化；由你精确控制哪些内容向前携带 |
| 下一步会产生大量只需要结论的输出 | **Subagent** | 中间工具噪音留在子上下文里；只有结果回来 |
