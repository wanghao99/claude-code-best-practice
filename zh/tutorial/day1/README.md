---

你已经装好了 Claude Code。然后呢？这篇指南带你走过三个使用层次 — 每一层都让你对 Claude **怎么**完成工作拥有更多控制权。

可以把它想象成雇人：
1. **Prompting（直接提问）** = 在街上问一个陌生人路怎么走
2. **Agents（代理）** = 雇一个总是按固定方式做事的专员
3. **Skills（技能）** = 这位专员针对特定任务受过专门训练

---

## 第 1 层：Prompting（直接问就行）

> 打个比方：像给一个懂很多的朋友发消息。你问"卡拉奇的天气怎么样？"，对方会给*一个*答案 — 但你不知道他是查了天气 App、看了窗外，还是凭记忆猜的。

打开终端，输入 `claude`，你就进入对话了。试着输入：

```
what is the weather in Karachi?
```

Claude 会回答 — 但它**怎么**回答是不可预测的。它可能会：
- 调用训练数据（可能已经过时）
- 搜索网页（如果网页工具可用）
- 给一个泛泛的回答，而不是实时数据

对于快速问答这完全够用！但如果你需要**稳定、可靠的结果**，光靠提问是不够的。

### 直接提问最适合的场景

- 问关于你代码库的问题（"这个文件是干什么的？"）
- 写或改文档（"把封邮件改得更专业一点"）
- 头脑风暴（"给这个活动出 5 个标题"）
- 解释东西（"像对非开发者那样给我解释这个报错"）

### 局限

每次你问"天气怎么样？"，Claude 取数据的方式都可能不同 — 甚至根本不去取真实数据。没法保证它两次用同一个来源、同一种方法。

---

## 第 2 层：Agents（请一位专员）

**agent** 就是 Claude 扮演一个特定角色 — 相当于给一个职位头衔。

> 打个比方：餐厅后厨。没有 agent 时，你随便走进一间后厨喊"给我做份意面！"— 听到的人可能给你煮包方便面，也可能做一桌意式大餐。有了 agent，你雇了一位**意面主厨**，他的岗位职责写着："永远用新鲜食材，永远煮到弹牙，永远按同样方式摆盘。"现在你知道自己每次会得到什么了。

同样的思路放到 Claude 上：

> **没有 agent：**你问 Claude "迪拜天气怎么样？"
> 它可能查训练数据、搜网页、或者凭感觉猜。你不知道它会怎么做。
>
> **有 agent：**一个 `weather-agent` 有清晰的岗位职责：
> "永远查 Open-Meteo API 的迪拜数据。永远按固定格式返回温度。"
> 同样的问题，同样的做法，每次都是。

### 本仓库的真实例子

这个仓库里就有一个 `weather-agent` — 它的全部职责就是获取迪拜的温度。它和直接提问的区别：

| | 直接提问 | Agent |
|---|---|---|
| **数据来源** | 不确定，哪里都可能 | 永远是 Open-Meteo API |
| **地点** | Claude 自己挑 | 永远是迪拜（纬度 25.2，经度 55.3） |
| **格式** | 随机的一段话 | 干净的温度值 + 单位 |
| **稳定性** | 每次都不一样 | 每次同一套方法 |

### 要点

Agent 给你的是**可预测性**。同样的问题 → 同样的方法 → 同样的质量。优势不在于 agent 更聪明，而在于它**稳定一致**。

## 第 3 层：Skills（专项训练）

**skill** 是 agent（或 Claude 本身）可以使用的一项具体能力。

> 打个比方：新员工的培训手册。一个人入职后有角色（agent），但还要接受具体的培训模块 — 怎么用 CRM、怎么写方案、怎么开站会。每个培训模块就是一个 **skill**。角色决定他*是*什么；skill 决定他*怎么做*具体的事。

再想一个真实的人：

> **Shayan**（本仓库作者）有很多技能：
> - 工程技能 — 会写代码
> - 游戏技能 — 熟悉游戏机制
> - 阅读技能 — 能消化并总结长文档
>
> 每项技能都有自己的知识和方法。Shayan 会为合适的任务用合适的技能。

Claude 也是一样。`weather-agent` 有一个叫 `weather-fetcher` 的 skill：

- **agent**（`weather-agent`）= 职位是"天气播报员"的那个人
- **skill**（`weather-fetcher`）= 关于*如何*取天气数据的具体训练

这个 skill 里写着精确的指令：
1. 调用这个确切的 API 地址
2. 从响应的这个确切字段里提取温度
3. 按这个确切的格式返回

### 为什么要把 Agent 和 Skill 分开？

因为**一个 agent 可以有多个 skill**，**一个 skill 也能被多个 agent 复用**。

比如你创建了：
- 一个 `daily-report-agent`，负责总结你的一天
- 它可以用 `weather-fetcher` skill（取天气）+ `calendar-reader` skill（读日程）+ `email-summarizer` skill（总结邮件要点）

Skill 是可复用的积木。Agent 是使用积木的人。

---

## 串起来看

全貌如下：

```
第 1 层：PROMPTING
你 → "天气怎么样？" → Claude 自己想办法
                       （方法不可预测）

第 2 层：AGENTS
你 → 天气 Agent → 永远用同一套方法
                  （方法可预测）

第 3 层：SKILLS
你 → 天气 Agent → 用 weather-fetcher skill
                  （方法可预测 + 指令精确）
```

每往上一层，控制力更强：

| 层次 | 你控制什么 | 最适合 |
|-------|-----------------|----------|
| **Prompting** | 问题本身 | 一次性的快速问答 |
| **Agents** | 问题 + 谁来回答 | 可重复的任务 |
| **Skills** | 问题 + 谁来回答 + 怎么做 | 关键工作流 |

---

## 接下来做什么？

现在，先花时间待在**第 1 层** — 就是直接提问。在终端里跟 Claude 越聊越熟，你自然会慢慢发现哪些任务值得配一个 agent。
